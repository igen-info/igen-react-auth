# igen-auth maintenance workflow

## Purpose

Apply safe, minimal maintenance changes to the `@igen/auth` package.

## First checks

1. Inspect `package.json`, `tsconfig.json`, `eslint.config.mts`, and the touched source files.
2. Confirm whether the task affects the library API, demo app, package publishing, or only internal implementation.
3. Use `pnpm`, not npm or yarn, because this repository contains `pnpm-lock.yaml`.

## Build and lint policy

Use these commands as the baseline:

```bash
pnpm install
pnpm exec eslint .
pnpm build
```

Run `pnpm build:demo` if the change touches React provider behavior, Keycloak initialization, public imports, or the demo.

Do not use `pnpm test` as proof of correctness unless the placeholder test script has been replaced with real tests.

## TypeScript policy

- Keep `strict` TypeScript passing.
- Preserve explicit function return types.
- Use `import type` for type-only imports.
- Avoid `any` and broad casts.
- Prefer narrow exported types for public API surfaces.
- Do not weaken `tsconfig.json` unless the user explicitly asks and the reason is documented.

## Package publishing policy

Before changing package metadata, check:

- `name`, `version`, `type`, `main`, `types`, `exports`, and `files` in `package.json`.
- Whether `dist/` is generated by `pnpm build` rather than edited by hand.
- Whether README usage still matches the public API.

Do not bump the package version unless the task explicitly requests a release/version change.

## Recommended response after work

Report:

- Files changed.
- Commands run and results.
- Any command not run.
- Any compatibility risk.
